## 主な機能

隠しピンボールはネオン演出・連続ヒットのコンボ・フィーバーに対応。通常最大5倍、6ヒットで12秒間のフィーバーに入り最大10倍になります。火花・得点ポップアップ・ボールの軌跡を表示し、効果音（初期OFF）と演出は個別に切り替えられます。

逆走ハイウェイは地方を通過するたびに難易度が1段階上がります（Lv.1〜14）。対向車が少しずつ速くなり、出現間隔が短く、2台並んで来る確率も高くなります。帰路で同じ地方へ入る場合も上昇します。現在の難易度は画面に表示し、再挑戦ではLv.1に戻ります。

ホームで `PAINKILLER` と入力すると「逆走ハイウェイ」が開きます（大文字小文字不問、入力欄以外）。スマホでは「もうけメモ」を長押しし、「別の秘密のコマンド」に入力して実行します。出発後は左右キー／左右ボタンで対向車を回避。スコアの代わりに走行距離と通過インターを表示し、東京から北海道・四国・九州・沖縄などを巡って東京へ帰還すると一周クリア。そのままLv.14固定で次の周回へ進むエンドレス走行に移ります。累計走行距離・周回数を表示し、衝突するまで何周でも続けられます。距離と海上区間の道路接続はゲーム用です。衝突すると終了し、東京から再挑戦できます。一時停止・再開とホームへ戻る操作に対応します。記録は保存しません。

ホームで入力欄以外に「↑ ↑ ↓ ↓ ← → ← → B A」を入力すると、隠しピンボールを開けます。左右キーでフリッパー、Spaceで発射（画面ボタンでも操作可能）。スコア表示・時間制限なしで、落球後も再発射できます。「ホームに戻る」またはEscでいつでも終了します。再入場時は0点です。

- 売却取引の登録・一覧・編集・削除、商品画像1枚の登録／置換／削除
- 取引を残したまま返品登録・返品費用の更新、返品表示と費用だけの損失計上
- サイト別の手数料率と端数処理による手数料・利益の自動計算
- 商品名・サイト・タグ・販売月・期間で検索、検索結果のCSV出力
- 今月のダッシュボード、月別・年間・サイト別集計、利益グラフ、月間利益目標
- 月次レポートのPDF保存・印刷（売上・経費内訳・利益・日別利益グラフ、A4縦）
- ダッシュボードの表示月切替、前月との利益・販売件数・平均利益の比較、日別利益の販売カレンダー
- 前月比較では差額・件数差に加えて増減率と増減の方向を表示（前月が0・マイナスの場合は差で比較）
- 購入履歴の登録・一覧・期間検索、購入／売却履歴へのタグ付けとタグ検索
- ダークモード（ブラウザーに保存）
- 入力途中の下書き自動保存・復元・削除（売却取引の登録／編集、購入履歴の登録）
- PC・タブレット・スマートフォンの画面幅に応じた表示（取引一覧は1024px以下でカード表示、その他の一覧表・カレンダーは横スクロール）
- 送料・梱包テンプレートの保存・編集・削除、取引登録／編集時の費用反映
- 値下げシミュレーション：送料・手数料・仕入価格・その他経費・確保したい利益から、最低販売価格と値下げ可能額を計算

メニューの「値下げシミュレーション」で現在価格と各費用を入力し、「値下げ可能額を計算」を押します。確保したい利益を0円にすると赤字にならない最低価格を確認できます。手数料はサイト設定（その他は入力料率）と設定の端数処理を使い、値下げ後の価格で再計算します。入力・結果は保存せず、取引・集計には反映しません。

対応サイトはメルカリ・ラクマ・Yahoo!フリマ・その他です。購入履歴は売却の仕入価格や利益に自動反映しません。購入履歴の編集はタグのみで、購入履歴の削除機能はありません。認証・ユーザー別データ分離・在庫管理・確定申告・外部API連携は未実装です。

「設定」→「テンプレートを管理する」で、名前・配送方法・梱包内容・送料・梱包費を保存できます。取引登録／編集画面で選ぶと、送料と梱包費の合計が送料欄に入り、利益に反映されます。反映後の金額は調整できます。取引には合計費用のみを保存し、テンプレートを編集・削除しても過去の取引金額は変わりません。

入力途中の内容は同じブラウザーに自動保存されます。「下書きを復元」で再開でき、「下書きを削除」で保存内容を消せます（入力欄は残ります）。新規売却・取引ごとの編集・購入登録でそれぞれ1件を保持し、新しい入力で上書きします。登録・更新成功時に該当する下書きを削除し、入力エラー・通信失敗時は残します。写真は再選択してください。下書きはDB・集計には反映せず、他の端末・ブラウザーとは共有しません。ブラウザーの保存データを消すと下書きも消えます。JavaScriptまたはブラウザーの保存機能が無効の場合は利用できません。

売却・購入の登録は、同じフォームの再送（連打・通信失敗後の再試行を含む）による二重登録を防止します。登録済みの場合は案内を表示します。別の商品を同じ内容で登録する場合は、新しい登録画面を開いてください。売却編集・購入タグ編集は、画面を開いた後に別の画面で更新されると保存を止め、入力を残して最新内容の確認を案内します。商品名はNBSPなどの空白だけでは登録できません。

更新後の初回起動時に、再送IDと履歴・設定・送料テンプレートの版番号を管理する5テーブルを自動作成します。既存の取引は保持します。更新前から開いている入力画面は開き直してください。古い編集下書きは自動上書きを防ぐため、そのまま保存できない場合があります。内容を控え、最新の編集画面に必要な変更を入力してください。

取引の削除も、確認画面を開いた後に編集・返品保存された場合は停止します。警告から最新の削除確認画面を開き直してください。取引・タグ・画像は再確認するまで保持されます。

返品登録・返品費用の更新も、画面を開いた後に別の画面で変更された場合は保存を止めます。入力金額を残して最新の返品画面へのリンクを表示するので、内容を控えて開き直し、保存済みの金額を確認してください。

設定の手数料率・端数処理・利益目標も、別タブで先に更新された場合は保存を止めます。入力を控えて「最新の設定画面を開く」から確認してください。初回設定の同時保存にも対応します。設定版の管理テーブルは起動時に自動追加され、既存の設定値は保持されます。

送料テンプレートの編集・削除も、別タブで更新された場合は停止して最新画面の確認を案内します。写真の容量超過時は元の取引編集画面へ戻り、下書きの復元または再入力を案内します。容量を超えた送信内容は自動では復元できないため、写真も選び直してください。

登録・変更・削除などのフォーム送信には、不正送信を防ぐCSRFトークンを自動で付けます。画面を長時間開いたままにした場合やアプリの再起動後など、セッションが切れていると保存せずにエラーを表示します。画面を開き直し、下書きがあれば復元して送信してください。写真は選び直してください。この対策はログインやデータの閲覧制限を追加するものではなく、公開デモは引き続き全閲覧者でデータを共有します。

## 使用技術

月次レポートは「収支レポート」で保存する月を選ぶか、ダッシュボードの「この月のレポートをPDF保存・印刷」から開きます。「PDF保存・印刷」でブラウザーの印刷画面を開き、送信先に「PDFに保存」を選びます（A4縦・倍率100%・ヘッダーとフッターはオフを推奨）。経費は送料・梱包費、販売手数料、仕入価格、返品費用の合計です。返品は元の販売月に費用のみ計上し、独立した購入履歴は含みません。取引のない月も0円で出力できます。JavaScript無効時はブラウザーの「印刷」を使用してください。

## 公開デモの仕様

`demo`プロファイルは外部DB不要です。起動時に架空の売却3件・購入1件・タグ・仮の手数料設定を用意し、すぐに登録や集計を試せます。画面に公開デモの案内を表示します。

ホームには初回設定を案内する文章が常に表示されますが、demoでは仮設定が投入済みなので、その操作をしなくても登録できます。

**データ・設定・アップロード画像は全閲覧者で共有されます。個人情報、実際の取引、私的な写真は入力しないでください。** DBはメモリー上にあり、再起動で初期サンプルに戻ります。Renderの画像保存領域も一時的です。手数料率は操作体験用の例で、各サイトの現行料金を保証しません。

画像を起動時に一括削除する機能はありません。同じDockerコンテナの再起動ではDBだけが初期化され、画像ファイルは残ります。画面の「再起動でリセット」という案内は、画像の削除まで保証するものではありません。現在のCompose構成ではコンテナの削除・再作成で画像も破棄されます。

Renderの無料Webサービスは一定時間アクセスがないと休止し、次のアクセスで起動待ちが発生します。常時すぐに応答することが必要なら、有料プランの選定が必要です。[無料プランの公式仕様](https://render.com/docs/free)

## 起動方法

### Dockerだけでデモを起動

Docker Desktop等を起動して、リポジトリのルートで実行します。JavaやMySQLの個別インストールは不要です。

```sh
docker compose -f compose.demo.yaml up --build -d
```

`http://localhost:8080/` を開きます。停止・コンテナ削除は `docker compose -f compose.demo.yaml down`。再起動するとDB内の入力データは初期化されますが、画像は同じコンテナ内に残ります。初回ビルドでは依存関係をダウンロードしてテストを実行します。

### Javaだけでデモを起動

Java 21を用意し、Windowsでは次を実行します。

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=demo" "-Dspring-boot.run.arguments=--server.address=127.0.0.1"
```

macOS / Linuxでは `sh ./mvnw spring-boot:run -Dspring-boot.run.profiles=demo -Dspring-boot.run.arguments=--server.address=127.0.0.1`。ブラウザーで `http://localhost:8080/` を開きます。

### MySQLへ保存する個人利用

Java 21とDockerを用意します。`demo`プロファイルを指定しない場合はこちらです。

```powershell
docker compose up -d db
.\mvnw.cmd spring-boot:run
```

`http://localhost:8080/` を開き、最初に「設定」で3サイトの手数料率と端数処理を入力してください。MySQLの起動直後に接続できない場合は、`docker compose logs db` で起動完了を確認してからアプリを再起動します。

この構成は同じPCからの単一利用者向けです。DBは既存の `pf-db-data` ボリューム、画像は `uploads/images/` に保存します。両方をバックアップしてください。起動時の `schema.sql` は不足テーブルを作成しますが、既存スキーマの移行はしません。ポート8080を他のアプリが使用中なら停止するか別ポートを指定します。

### Renderへ公開（管理者）

1. この変更を含むブランチをGitHubへpushします。
2. [Render Dashboard](https://dashboard.render.com/) でGitHubを連携し、New → Blueprintからこのリポジトリと反映済みブランチを選択します。
3. `render.yaml` を読み込み、Docker・Free・`SPRING_PROFILES_ACTIVE=demo` を確認してデプロイします。DBサービスの追加は不要です。
4. Liveになったら、発行されたHTTPS URLでホーム・取引登録／編集／削除・検索・CSV・レポートを確認します。`/healthz` はDB疎通成功時に200と `{"status":"UP"}` を返します。
5. このREADMEの「公開URL」を実際のURLへ置換します。サービス名からURLを推測して記載しないでください。

構成と確認手順は [公開・運用手順](docs/deployment.md) を参照してください。

## テスト

```powershell
.\mvnw.cmd -B -ntp verify
```

macOS / Linuxは `sh ./mvnw -B -ntp verify`。テスト専用H2を使用し、個人利用のMySQLには接続しません。入力検証、計算、CRUD、検索・CSV、画像処理、タグ、購入履歴、デモの初期化と画面表示、DBのヘルスチェックを確認します。
